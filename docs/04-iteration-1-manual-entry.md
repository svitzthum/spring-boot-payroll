# Iteration 1 — Manual Entry of Monthly Working Hours

## Goal

One complete vertical slice through the hexagon: a managing director records the
actual hours worked by an employee for a given month through a REST endpoint,
the value is persisted in PostgreSQL, and the behaviour is covered by tests.

## In scope

- Domain model of the monthly working hours aggregate, free of framework types.
- Inbound port for recording and querying monthly hours, implemented by an
  application service that owns the transaction boundary.
- Outbound port for persistence, implemented by a JPA adapter against a
  PostgreSQL schema managed by Flyway, including the unique constraint on
  `(employee_id, period)` and the optimistic locking column.
- Web adapter with `PUT /api/v1/employees/{employeeId}/working-hours/{yearMonth}`
  (idempotent upsert of the absolute monthly value) and `GET` endpoints for a
  single month and for all months of a year.
- Bean Validation on the request payload and RFC 9457 `ProblemDetail` responses.
- Tests: domain unit tests, application service tests against a fake outbound
  port, web slice tests, Testcontainers integration tests, and an ArchUnit test
  guarding the dependency rule.

## Out of scope (moved to later iterations)

- Scheduled import from the external time tracking system and its outbound port.
- `time_tracking_import` and `working_hours_revision` tables.
- Source precedence rules between manual entry and import.
- Optimistic locking exposed to clients via `ETag` / `If-Match`.
- Security, authentication and tenant isolation.

## Steps

1. **Build and infrastructure** — add validation starter, Flyway
   (`flyway-core`, `flyway-database-postgresql`), Docker Compose support,
   Testcontainers and ArchUnit to `build.gradle`; add `compose.yaml` with a
   PostgreSQL service; configure `application.yaml` (`ddl-auto: validate`,
   `open-in-view: false`, Flyway, logging).
2. **Domain** (`workinghours.domain`) — `MonthlyWorkingHours` aggregate with
   `WorkDuration`, `AccountingPeriod`, `EmployeeId` and `WorkingHoursSource`.
   The invariants (non-negative duration, plausible upper bound, normalised
   period) live here and are unit tested without Spring.
3. **Application** (`workinghours.application`) — inbound ports
   `RecordWorkingHoursUseCase` and `GetWorkingHoursQuery` with their command
   records, outbound ports `WorkingHoursRepository` and `EmployeeDirectory`, and
   a transactional service implementing the upsert semantics and the functional
   checks: employee exists and is active, period is not in the future.
4. **Persistence adapter** (`adapter.out.persistence`) — Flyway migrations
   `V1__init.sql` (three tables, foreign keys, unique index, check constraints)
   and `V2__demo_data.sql`; JPA entities, `YearMonth` converter, JPA auditing,
   Spring Data repositories, mapper, and the port implementation that translates
   constraint violations into a domain level conflict.
5. **Web adapter** (`adapter.in.web`) — controller, request and response records
   using ISO 8601 durations, a `@WholeMinutes` validation constraint, Jackson
   configured to serialise `Duration` as an ISO string, and exception handling
   via `@RestControllerAdvice` returning `ProblemDetail`.
6. **Tests and guardrails** — application service tests with a fake repository,
   `@WebMvcTest` for validation and status codes, Testcontainers integration
   test including a repeated call proving idempotency and a duplicate insert
   proving the unique constraint, plus the ArchUnit dependency rule test.

## Step 1 in detail — planned setup

### Dependencies to add to `build.gradle`

| Dependency | Configuration | Purpose |
| --- | --- | --- |
| `spring-boot-starter-validation` | `implementation` | Bean Validation on request payloads |
| `spring-boot-starter-actuator` | `implementation` | health endpoint for the Compose setup |
| `org.flywaydb:flyway-core` | `implementation` | schema migrations |
| `org.flywaydb:flyway-database-postgresql` | `runtimeOnly` | PostgreSQL support for Flyway |
| `spring-boot-docker-compose` | `developmentOnly` | starts the database on `bootRun` |
| `spring-boot-testcontainers` | `testImplementation` | `@ServiceConnection` wiring |
| `org.testcontainers:testcontainers-postgresql`, `:testcontainers-junit-jupiter` | `testImplementation` | PostgreSQL container in tests |
| `com.tngtech.archunit:archunit-junit5` | `testImplementation` | enforce the hexagon dependency rule |

The starters `spring-boot-starter-webmvc` and `spring-boot-starter-data-jpa`
generated by Spring Initializr stay as they are.

### `compose.yaml`

A single `postgres` service (`postgres:18-alpine`) with database, user and
password `payroll`, port `5432` exposed and a `pg_isready` healthcheck so
Docker Compose support and Testcontainers behave consistently.

### `application.yaml`

| Property | Value | Reason |
| --- | --- | --- |
| `spring.jpa.hibernate.ddl-auto` | `validate` | Flyway owns the schema, Hibernate only verifies the mapping ([ADR 0001](./adr/0001-postgresql-with-flyway.md)) |
| `spring.jpa.open-in-view` | `false` | no lazy loading outside the transaction; the adapter maps to domain objects anyway |
| `spring.jpa.properties.hibernate.jdbc.time_zone` | `UTC` | deterministic timestamps |
| `spring.flyway.locations` | `classpath:db/migration` | explicit migration location |
| `spring.jackson.datatype.datetime.write-durations-as-timestamps` | `false` | required for `PT152H30M` instead of numeric seconds ([ADR 0003](./adr/0003-store-durations-as-minutes.md)) |
| `management.endpoints.web.exposure.include` | `health,info` | minimal actuator surface |

No datasource URL is configured for local development — Docker Compose support
derives it from `compose.yaml`, and tests derive it from the container via
`@ServiceConnection`.


## API sketch

```
PUT /api/v1/employees/{employeeId}/working-hours/2026-08
{ "workedTime": "PT152H30M" }
→ 200 OK  { "employeeId": "...", "period": "2026-08", "workedTime": "PT152H30M", "source": "MANUAL" }

GET /api/v1/employees/{employeeId}/working-hours/2026-08
GET /api/v1/employees/{employeeId}/working-hours?year=2026
```

Working time is exchanged as an ISO 8601 duration and stored as whole minutes,
see [ADR 0003](./adr/0003-store-durations-as-minutes.md).

Errors are returned as `application/problem+json`:

| Situation | Status |
| --- | --- |
| Unknown employee | `404 Not Found` |
| Invalid payload or period format | `400 Bad Request` |
| Duration with sub-minute component or negative duration | `400 Bad Request` |
| Inactive employee, period in the future | `422 Unprocessable Entity` |
| Concurrent modification detected | `409 Conflict` |
